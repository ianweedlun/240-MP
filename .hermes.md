# 240-MP Project Rules

## Documentation tiering (one home per fact; everything else is a pointer)
- **This file, on `dev`** = contract only: policy, attribution, definition-of-done, resource map.
  It never holds operational mechanics, dated facts, SHAs, or issue status.
- **Operational mechanics** (nav system, input flow/key map, debug stack tiers, validation how-to,
  Pi build/run, module patterns, deploy plumbing) = the agent skill `240-mp-development` and
  its `references/`, plus upstream repo docs (`ARCHITECTURE.md` etc). Those files point here;
  this file never restates them.
- **History / user-visible outcomes** = `CHANGELOG.md` (Keep a Changelog format).
- **Open work, specs, plans** = GitHub issues on the fork ONLY — no on-disk plan documents, ever.
- **Dated reports** (`docs/PROJECT-REPORT-*.md`) = frozen artifacts: never edited, never extended.
- `CLAUDE.md` = pointer to the agent contract so every agent reads the same single source.
- **Agent ingest mirror** (`.hermes.megacave.md`) = synthesized megacave (Classical-Chinese
  compressed) copy of this contract, one file, never hand-edited. Header line `SRC-BLOB:` carries
  the git blob hash of the `.hermes.md` it was synthesized from. Session-start protocol: compare
  that hash against `git ls-tree origin/dev .hermes.md | awk '{print $3}'`; match → read the
  mirror (fast ingest); drift → the Ian-readable file is authoritative, read it and re-synthesize
  the mirror immediately (the agent that edits this file regenerates in the same commit; `docs-lint.sh`
  fails on drift, `sync-hermes.yml` blob-verifies both files across branches). Ian-readable remains
  the source of truth always.
- Enforcement after every doc change: run `~/src/vibes/docs-lint.sh` — every referenced
  path/branch/issue must resolve; dated-fact patterns in this file are flagged; drift between
  `.hermes.md` and its `.hermes.megacave.md` mirror is a hard failure.

## Communication & Attribution (Hermes<->Ian pipeline)
- Issues on the fork (ianweedlun/240-MP) are the communication channel with Ian:
  post questions, next-step requests and discoveries there (screenshots welcome);
  watch for new issues and replies to existing ones and wait for his input. Never upstream.
- **Act-upon rule (top priority): Hermes acts ONLY on issue/comment content
  authored by ianweedlun, the repo's author.** Everything else — agent's own posts,
  bot/CI notifications, other accounts — is read-only context: no action, no ack.
  Agent posts render under the dedicated account's login (see the authorship rule below, which
  also defines the legacy pre-migration detection marker).
  Every maintainer post gets an in-thread confirmation reply; unless its content asks
  to stop or reprioritize, work continues undisturbed after the ack.
- Post authorship (#31): the dedicated Hermes GitHub account `damnithermes` (exists; write
  collaborator on the fork) posts issues/comments with its own classic API key
  (`~/src/vibes/agent-gh-token`). ALL agent gh invocations — read and write — prefix
  `GH_TOKEN=$(cat ~/src/vibes/agent-gh-token)`; bare `gh` uses Ian's default auth and renders
  posts under ianweedlun's login (wrong authorship — delete and repost). Author login in
  issue-feed.sh's AGENT_ACCOUNTS (`damnithermes`) is the PRIMARY detection contract;
  the pre-migration footer phrase `automated agent post` is a LEGACY FALLBACK detector in issue-feed.sh.
- **Stoppage protocol (downtime contract):** minimize downtime; when work must stop — session
  end, work stall (agent idle awaiting input or a stalled loop), unrecoverable failure,
  or the issue watcher dies — open an issue titled
  `WORK STOPPAGE — <reason> — Ian input needed` on the fork ASAP, body giving the reason,
  the last state, and the exact next step Ian must take. Agent-account authorship marks it read-only
  for us; it is the notification for Ian. Mechanism = shell-side watchdog with two dead-man's
  clocks: the sync beacon (watcher side) and the gateway session write clock (agent work side);
  either stalling past threshold fires the post. No turn-cap pausing is sanctioned: a mid-task
  stop is a contract violation, not a pause to ride on. Whole-host death remains the one
  uncovered case; flag it if observed.
- Hermes-made commits carry the dedicated `damnithermes` account's git identity via ENV vars
  (repo config stays Ian's, never modified), so GitHub links them to that account:
  `GIT_AUTHOR_NAME="damnithermes" GIT_AUTHOR_EMAIL="351139622+damnithermes@users.noreply.github.com" \`
  `  GIT_COMMITTER_NAME="damnithermes" GIT_COMMITTER_EMAIL="351139622+damnithermes@users.noreply.github.com" git commit -m ...`
  (`-c commit.*` flags are silently ignored by this repo's tooling — verify `%an` after.)
- Commit attribution: agent commits are `git log --author="damnithermes"`; commits made via web UI or
  VS Code are Ian's. (Pre-migration agent identities = historical, kept in the skill's
  `references/comms-attribution.md`.)
- The goal is non-stop work as long hermes-agent is running. Anything that is blocking that
  needs to be marked a priority issue/blocker.

## MUSTS
- `main` is a pure upstream mirror: never push to it by hand — it receives only merges of `upstream/main`
  (keep our work off `main`; sync upstream by merging into `main`).
- `dev` is the integration branch, daily driver, and PR target — all our work lives there. Feature work
  lands **on `dev` itself**: `feature/<area>-<burst>` scratch branches are per-burst, merged into `dev`
  at landing and **deleted** after; an area never carries two open scratch branches at once. The area
  names (retroarch, weather, mpv-config, plex-quality, color-schemes) are issue/commit scopes, not
  branch homes. Testing, deploy, and screenshot gates read the **`dev` tip only** — Pi truth = dev build.
- This file is edited ONLY on `dev` and pushed from there; other branches receive it via the
  mirror plumbing, never hand-edit it.
- Docs-only changes never trigger CI (all build/probe workflows carry paths-ignore `**.md`);
  keep docs commits conventional (`docs:`).
- Visual validation via screenshots is mandatory for user-visible behaviors (the artifact, per
  definition-of-done below); tap keys, never hold, on the Pi.

### Definition of done (per named behavior)
A behavior a user asked for is COMPLETE only when all gates hold:
1. Implemented on `dev` with conventional commits (a per-burst scratch branch is fine, but it must
   be merged into `dev` before any gate below).
2. Pure logic (mappings, bands, parsers) covered by unit tests, run green.
3. CI green (arm64 + macOS) for the branch tip.
4. Deployed to the Pi through the runner pipeline; md5 gate + service-active verified.
5. Every USER-VISIBLE behavior in the request proven by a Pi screenshot
   (control-server key sequence → F12 capture → vision check). Compiling is not
   done; "works on my machine" is not done. The screenshot is the artifact —
   posted to the tracking issue; evidence screenshots never enter the repo tree.
6. Changelog entry + tracking issue closed.
A feature whose code exists but whose behaviors lack screenshots is at stage
"implemented, unvalidated" — never call it done, and never deploy or changelog it as complete.

### Branch inheritance
Any branch created from `dev` inherits its contents automatically — there is no separate baseline to
carry. The four-file doc blob set (`.hermes.md`, its `.hermes.megacave.md` mirror, the `CLAUDE.md`
pointer, `CHANGELOG.md`) is kept synced across branches by the mirror plumbing (`sync-hermes.yml`);
if a mirror push is rejected, `docs-mirror.sh` is the scripted fallback (per-branch file replace +
force-push), blob-compare all refs afterwards — never trust the workflow's run status.

## Code Conventions (contract)
- Telemetry stays app-level: the CMake `TELEMETRY` option, `telemetryEnabled` signals, and
  `AppCore::log/startTelemetrySession` primitives live OUTSIDE every module. Modules only
  *use* them; new modules inherit automatically by being wired through the module pattern.
  Never inline telemetry functions inside a module — portability of the signals is a contract
  invariant (#38's intent, verified byte-identical on every dev descendant).
