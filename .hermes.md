## Navigation System

### App-level nav stack (Main.qml)
- `appNavStack: []` — array of `{source, params, listState}` pushed on navigateTo, popped on goBack
- `appCurrentParams` — current params dict passed to the active view
- `_startupNavigated` — flag: on first module load, pushes initial state and sets entry point from `startup_module` config

### Module Loader (Main.qml, line 238-284)
- Loads `views/ModuleList.qml` by default
- Each module view declares `signal navigateTo(path, params, listState)` and `signal goBack()`
- Main.qml's Connections bridges these to the nav stack:
  - `onNavigateTo`: pushes current state onto stack, sets new params, swaps Loader source
  - `onGoBack`: pops stack, restores params, swaps Loader source back
- Module views get `focus: true` and `item.forceActiveFocus()` on load

### ModuleList.qml (main menu)
- ListView of enabled modules from `appCore.scan_for_modules()`
- Each row: `{name, entry_point, params?}` — params come from backend's `get_menu_entries()`
- Up/Down: cycle currentIndex with wraparound
- Return: calls `appRoot.navigateTo(row.entry_point, row.params, {currentIndex})`
- Escape/Backspace/Back: navigates to `views/Settings.qml`

### Settings.qml
- Flat model of section headers + selectable rows
- `list_single`: left/right cycles options, auto-saves to config
- `submenu`: Return opens ModuleSettings.qml, Update.qml, or RemapControls.qml
- `quit`: opens quit confirmation overlay (choice list)
- Escape/Backspace/Back: calls `goBack()`

### RemapControls.qml
- 6 rows (up/down/left/right/select/back) showing current remap
- Return on a row: enters capture mode (`capturing=true`)
- Capture overlay: InputManager swallows all real input, reports via `auxButtonPressed` signal
- Escape/Backspace/Back during capture: cancels
- On finish: clears any duplicate remap, saves to `config.json` → `app.remote_keymap.<action>`

### Input flow
1. Gamepad → SDL poll (16ms) → `handleButton`/`handleAxis` → `pressAction`/`releaseAction`
2. `pressAction` → `beginPress` → `deliverPress` → `postKey` (synthesized QKeyEvent with `kSyntheticScanCode=0x240F00D`)
3. Keyboard → eventFilter → `deliverPress` (same synthesized event path)
4. Consumer Control (evdev) → `onConsumerControlReadable` → `beginPress`/`releaseAction`
5. Media keys → `mpvKeyRequested` signal → mpvController.sendKey (bypasses QML)

### Key mapping
- Gamepad: SDL button → Action enum (Up/Down/Left/Right/Select/Back/PlayPause)
- Action → Qt key: Up=103, Down=108, Left=105, Right=106, Select=Return(28), Back=Escape(1), PlayPause=Space(57)
- Synthesized events carry `nativeScanCode=0x240F00D` so eventFilter can distinguish them from real keys
- Remapped keys: `config.json` → `app.remote_keymap.<action>` → `m_keyRemap[qtKey] = action` (additive)

### Key behaviors per view
- ModuleList: Escape → Settings; Return → module entry_point; Up/Down → list navigation
- Settings: Escape → goBack; Return → submenu/quit; Left/Right → cycle options
- Module views: Escape → goBack; Return → select item; Up/Down → list navigation
- Player views: Escape → goBack; Return → play/pause; Up/Down → seek; Left/Right → seek fine
- RemapControls: Return → start capture; Escape → cancel; Return on row → capture

### Key remap (InputManager.cpp)
- `m_keyRemap[qtKey] = action` — additive, never removes defaults
- Capture mode: `m_remapCapture=true` → eventFilter emits `auxButtonPressed(ke->key())` instead of delivering
- Right Shift → Back (when no text field focused)
- Media keys → mpv IPC (volume, play/pause, etc.)

## Debug Stack

### Startup (on Pi)
```bash
systemctl start 240mp-debug.service
```
Starts three services:
1. **MJPEG stream** (`stream_screen.sh`): ffmpeg fbdev → HTTP MJPEG on port 8080
2. **Control server** (`control_input.py`): HTTP POST `/key` on port 8081, uses `evemu-event` on `/dev/input/event0`
3. **Viewer** (Python HTTP server): serves `viewer.html` on port 8082

### Viewer & Controller (http://execubot.weedlun.me:8082)
- `viewer.html` — MJPEG stream + key buttons + log
- Key buttons: ESC, Backspace, TAB, Up, Return, Down, Left, Space, Right, VolumeUp, VolumeDown, Mute
- All buttons send POST to `http://execubot.weedlun.me:8081/key` with `{"key": "KeyName", "press": true}`
- Control server maps key names to evdev codes (KEY_* values) and sends via `evemu-event`
- Stream auto-refreshes every 5s via img src toggle

### Key codes (evdev / Linux KEY_*)
Up=103, Down=108, Left=105, Right=106, Return=28, Escape=1, Backspace=14, Space=57, Tab=15
VolumeUp=115, VolumeDown=114, Mute=113

### Validation workflow
1. Deploy new build to Pi (git sync + build + install)
2. Reboot Pi (or restart 240mp.service)
3. Open viewer at http://execubot.weedlun.me:8082
4. Use controller buttons to test navigation
5. Verify visual output on stream matches expectations
6. Test: Navigation through all menus, especially modules we just modified
